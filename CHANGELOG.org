#+title: Changelog
#+options: toc:2 num:nil

All notable changes to Shiso are documented here.

The format is inspired by [[https://keepachangelog.com/][Keep a Changelog]].
Versions match the =:version= in =shiso.asd= when set; otherwise
entries are dated by release milestone. Each release opens with its
highlights; the sections after them list every change.

* Unreleased

Run a Shiso site in production with less risk, and in more than one
language.

- *Settings.* Configure Shiso and every module in one file with
  =shiso:configure=, and give each machine its own values in its
  environment. A misconfigured server refuses to start and tells you
  why.
- *Safety.* A built program assumes production, so development
  features stay off. Mark a setting =:secret t= to keep its value out
  of committed files and logs.
- *Start-up.* =shiso:start= sets up the server and the database for
  you, so your application has less code to maintain.
- *Languages.* Serve your site in any language, or several, including
  Shiso's own text. Your code calls =shiso:translate=, and translators
  work in their own files.
- *HTTP errors.* Every error returns the right status and a page you
  design with =define-error-page=; JSON and HTMX clients get responses
  they can use. A failed request leaves no partial changes in the
  database.
- *Debugging.* In development, =:debugp :repl= opens the Lisp debugger
  on an error, so you can fix the code and retry the request.
- *Routing.* Controllers receive URL parameters already checked and
  converted, as in ="/<int:id>"=, so they need less code. Redirects
  and logins work in modules mounted at a prefix.

** Added

- HTTP error handling, in =src/errors.lisp=:
  - Stop a request from anywhere with =abort-with=, or signal a
    condition: =http-error=, =bad-request=, =unauthorized=,
    =forbidden=, =not-found=, =method-not-allowed= or
    =internal-server-error=.
  - Define an error page with =define-error-page=, for one status,
    =:4xx=, =:5xx=, or =t= for all.
  - Map your own conditions to statuses with =condition-http-status=.
  - Use =get-or-404= and =found-or-404= to return a 404 when a row
    doesn't exist.
  - JSON clients get RFC 9457 =application/problem+json=. HTMX
    requests get a fragment (=*fragment-p*=), and =HEAD= requests an
    empty body.
  - If an error page fails, Shiso serves =static/errors/<status>.html=,
    then plain text.
  - In debug mode, requests from your own machine get a debug 500
    page, and a 404 page that lists the routes tried (=*debug-404*=).
  - With =:debugp :repl= (the =:server/repl-debugger= setting), an
    unexpected error opens SLY's or SLIME's debugger. Its restarts are
    =retry-request=, =show-debug-page= and =show-error-page=.
  - =*log-client-errors*= decides which client errors are logged.
  - Error pages render with the request's locale and =shiso:*request*=,
    so =translate=, =url= and your page components work in them.
  - =reason-phrase= returns a status's standard text.
  - See the how-to "Handle HTTP errors" and the demo in
    =examples/errors-demo=.
- New projects include =static/errors/500.html=, a self-contained page
  for when the application's error page fails. They also include
  example =define-error-page= forms in =src/routes.lisp=.
- Typed route parameters: in ="/<int:id>"=, the controller receives
  =id= as an integer, and a non-numeric value returns 404. The
  converters are =int=, =slug=, =uuid= and =str=; add more with
  =define-path-converter=. =url= accepts typed values.
- A request whose method no route on its path accepts gets a 405 with
  an =Allow= header. An =OPTIONS= request gets 204 and =Allow=
  (=*auto-options*=).
- Atomic requests: each POST, PUT, PATCH and DELETE request runs in one
  database transaction. An error that leaves the request rolls it back
  (=*atomic-requests*=).
- Settings, built on the =almighty-settei= library:
  - Declare a setting with =define-setting=. The kinds are
    =boolean-setting=, =integer-setting=, =string-setting=,
    =pathname-setting=, =choice-setting= and =list-setting=.
  - Read a setting with =setting=, and where its value came from with
    =setting-source=.
  - Also new: =per-environment=, =with-settings=, =on-setting-change=,
    =print-settings= and =redact=.
  - A value comes from the first of: the session, its environment
    variable, =.env= (development only), the project's =configure=,
    or its default.
  - =load-settings= reports every problem at once, in one
    =shiso:settings-invalid=.
  - See =org/src/settings.org=.
- =:shiso/environment=, set by =SHISO_ENV=, is =:development=, =:test=
  or =:production=. It defaults to development in a REPL and
  production in a built program. Shiso reads =SHISO_ENV= from =.env=
  on any machine.
- Shiso's own settings: =:shiso/site-origin=, =:server/host=,
  =:server/port=, =:server/debugp=, =:server/backend=, the
  =:database/= settings, and =:static/manifest=. =:database/password=
  is secret. The old variables =HOST=, =PORT=, =DEBUGP= and
  =DATABASE_PATH= still work.
- =shiso:connect-database= connects using the =:database/= settings.
  =shiso:setup-database= also creates the session table and any
  missing model tables. =define-application= accepts
  =:after-database=, a function Shiso calls once the database is
  ready.
- =shiso:site-origin= returns the site's scheme and host.
- =<app> settings [--changed]= lists the application's settings with
  their sources and documentation, secrets masked.
- New projects include =src/settings.lisp= and a git-ignored =.env=
  that sets =SHISO_ENV=development=.
- Internationalization with Fluent:
  - The API is =shiso:translate=, =with-locale= and
    =load-localisations=.
  - Catalogs are =.ftl= files in =locale/<locale>/=.
  - The locale middleware reads the =shiso_language= cookie, then
    =Accept-Language=.
  - =POST /i18n/set-language= (module =shiso-i18n=) saves the
    visitor's choice.
  - Framework text (validators, auth, admin) goes through =translate=,
    with English defaults.
  - Model field labels use ids of the form ={model}-{field}=.
  - Shiso vendors =fluent=, =parcom=, =plurals= and =filepaths=.
    Fluent is MPL-2.0.
  - Dates aren't localized for display. =local-time= still handles
    instants and widgets.
  - See tutorial 7 and the how-to, reference and explanation chapters.

** Fixed

- =cached-static= looked for files in the current directory, so a
  deployed binary started elsewhere produced unversioned URLs. It now
  uses the =static/= directory that =define-application= serves.
- Responses with status 428, 429 or 431 reached the client as an empty
  500, because Woo lacks their status lines. =shiso:start= now adds
  them.
- =define-route= with =:regexp t= dropped the regex captures and
  called the controller with no arguments.
- The admin returned 500 for a non-numeric ID in a URL, and a blank
  form for a missing row. Both now return 404.
- Trailing-slash redirect loops: =redirect-response= and =url= no
  longer add a trailing slash that =define-application='s 301 redirect
  removes. A module's index URL is now =/prefix=, not =/prefix/=.
- After login in a module mounted at a prefix, =?next== lost the
  prefix: =/= instead of =/staff=. Mounts now set Lack's =:script-name=
  to the prefix, and guards use the full path.
- The trailing-slash 301 now keeps the query string in =Location=.
- Every response set a session cookie and saved a session row, even
  for anonymous visitors. A CDN won't cache a page that sets a cookie.
  Shiso now creates a session only when you store something in it,
  such as a login or a CSRF token.

** Upgrading

1. Move your =src/config.lisp= values into =shiso:configure= in
   =src/settings.lisp=.
2. Remove your database setup code. =shiso:start= now connects and
   creates the tables.
3. Copy =static/errors/500.html= from a new project into yours.
4. To show your 404 page, replace =(http-response "Not found" :code
   404)= with =(s:abort-with 404)=.
5. Debug mode is now on in development. To turn it off, set
   =DEBUGP=false=.
6. Writes made before an error in a POST, PUT, PATCH or DELETE request
   are now rolled back. If your code relies on them, set
   =shiso:*atomic-requests*= to NIL.

** Changed

- =wrap-http-errors= handles errors in a request, replacing
  =wrap-error-logging=. In debug mode, an unexpected error shows the
  debug page instead of entering the debugger. Use =:debugp :repl= to
  enter it, with a restart to retry the request.
- 404, 400 and 403 responses render through the error-page registry
  instead of fixed text. This covers unknown paths, unparsable
  requests, bad CSRF tokens and guards. A wrong method on an existing
  path now returns 405, not 404.
- Logged backtraces omit the frames of the error handler itself.
- =shiso:start= loads the settings, sets up the database, and serves
  using the =:server/= settings. Its =:host=, =:port= and =:debugp=
  arguments set those settings for the run. Applications no longer
  connect to the database or read the environment themselves.
- =:server/debugp= is true in development, so an error shows the debug
  page. With =:debugp :repl=, it opens the debugger instead. Set
  =DEBUGP=false= to turn it off.
- Shiso logs each unexpected error once, with secrets masked and
  cookies left out. It always returns the 500 itself, so nothing else
  prints the error unmasked.
- =shiso:absolute-url= starts with =:shiso/site-origin=. For a request
  to another host, it uses that request's scheme and host.
- =run-cli= loads the settings first, and =setup-db= uses
  =setup-database=.
- The project template's =src/config.lisp= is replaced by
  =src/settings.lisp=.
- =shiso:current-path= returns the full request path (=script-name=
  plus =path-info=), not only the =path-info= after the mount.
- =canonicalize-path= and =canonicalize-redirect-url= are exported.

* 0.3

Make a site look and load the way you want.

- *Static files.* Browsers get new stylesheets and scripts as soon as
  you deploy, while unchanged files stay cached. =shiso:cached-static=
  gives each file a versioned URL.
- *Forms.* Make forms match your site's design while Shiso handles
  validation, errors, the visitor's input and CSRF protection.
  =field-context= gives each field's state as plain data, ready for
  any markup.
- *Scaffolding.* New projects start with their own page skeleton and
  form components, such as =ac-field=, ready to restyle.

** Added

- =shiso:cached-static= returns cache-busting static URLs. With a
  =staticfiles.json= manifest (production), it returns content-hashed
  paths. Without one (development), it appends =?v=<mtime>=. Unknown
  paths fall back to =static= and warn once.
- =(shiso:collectstatic :hash t)= writes =stem.<12-hex>.ext= copies
  next to the unhashed files, and a =<target>/staticfiles.json=
  manifest. Old hashed files stay, so rolling deploys are safe. Nested
  CSS =url()= references aren't rewritten.
- =shiso/static:reload-manifest= reloads the manifest from the REPL
  after a live =collectstatic=.
- In development, the static middleware strips a =.<hex>= segment
  before the extension, so manifest URLs work against module =static/=
  trees.
- =:ironclad= is a direct dependency, for SHA-256 fingerprints.
- Static-file tests in =t/static.lisp=.
- A headless forms API in =shiso/forms/context=: =field-context=,
  =form-field-by-name=, =cleaned-value=, =resolve-widget= and
  =request-form-data=. A form keeps validation, coercion, the
  visitor's input and errors as plain data. Markup is up to you.
- =render-field= and =render-fields= dispatch on a style first, then
  on the field. The default style is =t=. The admin always passes
  =:admin=, so your specializations can't change admin pages.
- =register-widget-field-class= and =widget-field-class= map a model's
  =:widget= keyword to a form-field class in =make-model-form=. Built
  in: =:email= maps to =email-field=.
- New projects include =src/hypermedia/form-components.lisp=, with
  =ac-csrf-input=, =ac-field= and =ac-fields=. They use
  =field-context=; restyle them by editing the file.
- The top-level =shiso= package re-exports the forms API.
- The todo example uses model forms for create and update, module form
  components, a compact add form built with =field-context=, an edit
  route, and =ac-csrf-input=.
- Form tests for =field-context=, password and email widgets, date
  parsing, =render-fields= row ids and =cleaned-value=.
- New projects include =src/config.lisp=, which reads =host=, =port=,
  =debugp= and =database-path= from the environment. =database-path=
  defaults to an absolute path under the XDG data home, and
  =DATABASE_PATH= overrides it.
- New projects include a project-wide hypermedia system
  (=<%application-name%>/hypermedia=). Its =ac-page-skeleton= sets
  the charset, viewport and CSRF meta tag, with hooks for CSS and JS.
- New modules include =hypermedia/package.lisp=, which re-exports the
  module's components.
- A new project's =main= calls =shiso:run-cli= with =:setup-db= and
  =:serve=, so commands such as =createsuperuser= work.

** Changed

- =render-form= adds a CSRF hidden input for methods other than GET.
  It honours a field's =:widget=, including =:password= and =:hidden=,
  and accepts =:style=. Use =field-context= and components for
  designed pages; =render-form= stays for the admin and prototypes.
- The login and signup pages use =render-form=, so password widgets
  work. They read the body with =request-form-data= and values with
  =cleaned-value=.
- Admin forms pass =:style :admin= to =render-form=.
- =date-field= accepts HTML =date= (=YYYY-MM-DD=) and
  =datetime-local= values, with optional seconds. A blank value parses
  as =NIL=.
- Updated docs: the forms reference (headless API, style dispatch),
  the CSRF how-to, the todo tutorial (05), the auth tutorial (06), and
  the CSRF helper in polls part 2.
- Scaffolder templates use separate keys: =new-application=
  substitutes =application-name=, and =new-module= substitutes
  =module-name=. They replace the shared =name= key.
- Skeleton file names and package prefixes use those keys, as in
  =<% @var application-name %>.asd= and =<% @var module-name %>.asd=.
- A new project's =build.lisp= and =Makefile= run =vend get=, then
  load and build with =build.lisp= alone.
- Updated docs: the scaffolder how-to and the CLI reference cover the
  new keys and files.
- Routing uses plain MyWay, without the namespace fork. Each module
  still has its own mapper, which holds its short route names
  (=:INDEX=). =shiso:url= with ="module:route"= finds the module, then
  the short name. =*global-routes-namespace*= and MyWay's =:namespace=
  are removed.

* 0.2 — 2026-07-17

Start and run real projects.

- *Scaffolding.* Make a working project or module with one command,
  such as =shiso new-application=, instead of copying an example.
- *Authentication.* Give your site sessions, logins and CSRF
  protection without building them. =createsuperuser= makes your
  first administrator.
- *Application binaries.* Add your own maintenance commands to your
  site's built program with =register-command=.
- *Documentation.* Learn Shiso from the first tutorial to the full
  reference, all under =docs/=.

This release includes the work landed through the =Updated
scaffolding= line of development.

** Added

- A CLI scaffolder: =shiso new-application= and =shiso new-module=.
  Its templates live under =skeleton/=, found through =SHISO_HOME=.
- Authentication: sessions, CSRF helpers, a login flow, and the
  =createsuperuser= management command.
- =shiso:run-cli= and =register-command=, for commands in application
  binaries.
- Basic logging.
- A Diátaxis documentation tree under =docs/=: tutorials, how-tos,
  reference and explanation.
- Field-type shorthand for =define-model=, better registry
  introspection, and proper interning of model classes.

** Changed

- More exports and utilities for app authors, such as =url=, CSRF
  token access and session table helpers.
- Admin links use =shiso/utils:url=.

** Removed

- Org sources are no longer the primary code. Plain =src/= is
  canonical again.

* 0.1 — 2026-02 … 2026-03

Build a site from reusable modules, with models, forms and an admin
from the first day.

- *Modules.* Build a site from modules mounted at URL prefixes, each
  with its own named routes. =define-module= declares one, and
  =define-application= mounts it.
- *Models and forms.* Store data in Mito-backed models declared with
  =define-model=, and accept it through forms with validators.
- *Admin.* Manage your data through CRUD pages for each model you
  register with =define-admin=.

** Added

- Module and application macros: =define-module=,
  =define-application=, and =define-route= with a route table.
- Named and regex routes, and helpers for requests and responses.
- Mito-backed models, forms and validators.
- An admin with a registry, CRUD pages and a module to mount.
- An early scaffold for applications and modules.
- Tests for routing and related core behaviour.

** Changed

- The route API is renamed toward =define-route=, with clearer export
  sets.
