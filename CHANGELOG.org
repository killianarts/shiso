#+title: Changelog
#+options: toc:2 num:nil

All notable changes to Shiso are documented here.

The format is inspired by [[https://keepachangelog.com/][Keep a Changelog]].
Versions match the =:version= in =shiso.asd= when set; otherwise
entries are dated by release milestone. Each release opens with its
highlights; the sections after them list every change.

* Unreleased

For running a Shiso site in production with confidence, and for sites
in more than one language.

- *Settings.* A project configures Shiso and every module in one
  place, and each machine says what it is in its environment, so
  projects no longer write their own configuration code. A server
  with a wrong setting refuses to start and says why, rather than
  failing later in a request, and a built program assumes production,
  so nothing meant for development is left on by accident.
- *Start-up.* =shiso:start= sets up the server and the database
  itself, leaving less code in each application.
- *Security.* Secrets stay out of committed files and out of logs.
- *Internationalization.* A site can be in a language other than
  English, or in several, Shiso's own text included, and translators
  work in their own files without touching the Lisp.
- *Routing fixes.* Redirects and logins behave under modules mounted
  at a prefix.
- *HTTP errors.* A controller signals =(s:abort-with 404)= from
  anywhere and the application designs each error page in one form.
  JSON and HTMX clients get answers they can use, a wrong method is a
  405, a failed POST leaves no half-written rows, and in development
  an error opens the debugger with the request waiting to be retried.

** Added

- HTTP error handling (=src/errors.lisp=): conditions =http-error=,
  =bad-request=, =unauthorized=, =forbidden=, =not-found=,
  =method-not-allowed=, =internal-server-error=; =abort-with=;
  =define-error-page= for a status, =:4xx=, =:5xx= or =t=;
  =condition-http-status= to map an application's own conditions to
  statuses; =get-or-404= and =found-or-404=. JSON clients get RFC 9457
  =application/problem+json=, HTMX requests a fragment
  (=*fragment-p*=), =HEAD= an empty body. If an error page fails,
  =static/errors/<status>.html= is served, then plain text. In debug
  mode, for requests from this machine only, the debug 500 page and a
  404 listing the routes tried (=*debug-404*=). =:debugp :repl= (setting
  =:server/repl-debugger=) opens SLY's or SLIME's debugger on an
  unexpected error, with =retry-request=, =show-debug-page= and
  =show-error-page= restarts. Client errors are logged by
  =*log-client-errors*=. Error pages render with the request's locale
  and =shiso:*request*= bound, so =translate=, =url= and page
  components work in them. =reason-phrase= gives a status's standard
  text. Docs: how-to "Handle HTTP errors"; demo: =examples/errors-demo=.
- New projects get =static/errors/500.html=, a self-contained page for
  when the app's own error page fails, and example =define-error-page=
  forms in =src/routes.lisp=.
- Typed route parameters: ="/<int:id>"= gives the controller an
  integer and makes a non-numeric value a 404. Converters =int=,
  =slug=, =uuid=, =str=, and =define-path-converter= for more. =url=
  accepts the typed values.
- 405 with an =Allow= header for a path some route serves with another
  method; =OPTIONS= for it gets 204 and =Allow= (=*auto-options*=).
- Atomic requests: POST, PUT, PATCH and DELETE run in one database
  transaction, rolled back when an error leaves the request
  (=*atomic-requests*=).
- Settings, on the =almighty-settei= library: =define-setting= (kinds
  =boolean-setting=, =integer-setting=, =string-setting=,
  =pathname-setting=, =choice-setting=, =list-setting=), =setting=,
  =setting-source=, =per-environment=, =with-settings=,
  =on-setting-change=, =print-settings=, =redact=. A value comes from
  the session, its environment variable, =.env= (development only),
  the project's =configure=, or its default. =load-settings= reports
  every problem at once in one =shiso:settings-invalid=. Docs:
  =org/src/settings.org=.
- =:shiso/environment= (=SHISO_ENV=): =:development=, =:test= or
  =:production=. Defaults to development in a REPL and production in a
  built program; =SHISO_ENV= in =.env= is read on any machine.
- Shiso's own settings: =:shiso/site-origin=, =:server/host=,
  =:server/port=, =:server/debugp=, =:server/backend=, the
  =:database/= settings (=:database/password= secret), and
  =:static/manifest=. The old variables =HOST=, =PORT=, =DEBUGP= and
  =DATABASE_PATH= still work.
- =shiso:setup-database= and =shiso:connect-database=: connect from
  the =:database/= settings, make the session table and each model's
  missing table. =define-application= takes =:after-database=, a
  function called once the database is set up.
- =shiso:site-origin=.
- =<app> settings [--changed]=: the application's binary lists its
  settings, sources and documentation, secrets masked.
- New projects get =src/settings.lisp= and a git-ignored =.env= with
  =SHISO_ENV=development=.

- Internationalization via a Fluent wrap (=shiso:translate=,
  =with-locale=, =load-localisations=). Catalogs are =.ftl= files
  under =locale/<locale>/=. Locale middleware reads the
  =shiso_language= cookie then =Accept-Language=. =POST
  /i18n/set-language= (module =shiso-i18n=) persists the choice.
  Framework strings (validators, auth, admin) go through =translate=
  with English =:default=. Model field labels use derived ids
  ={model}-{field}=. Vendored =fluent=, =parcom=, =plurals=,
  =filepaths= (Fluent is MPL-2.0). Date *display* localization is
  not included; =local-time= still owns instants and widgets.
  Docs: tutorial 7, how-to, reference, and explanation chapters.

** Fixed

- A response with status 428, 429 or 431 reached the client as an
  empty 500: Woo has no status line for them. =shiso:start= adds the
  missing ones.
- =define-route= with =:regexp t= dropped the regex's captures and
  called the controller with no arguments.
- The admin answered 500 for a non-numeric ID in its URLs, and showed
  a blank form for a missing row; both are 404s now.
- Trailing-slash redirect loops: local =redirect-response= Locations
  and =url= reverses no longer re-add a trailing slash that
  =define-application='s 301 stripper removes. Module index reverse
  is =/prefix= not =/prefix/=.
- Login =?next== after a prefix mount: mounts set Lack
  =:script-name= to the prefix; guards rebuild the full path so
  =next=/staff= (not =next=/= when =path-info= is =/= inside the
  mount).
- Trailing-slash 301 preserves the query string on =Location=.

** Upgrading

Move a project's =src/config.lisp= values into =shiso:configure= in
=src/settings.lisp=, and let =shiso:start= set up the database. Debug
mode is now on in development; =DEBUGP=false= turns it off.

Error responses are pages now: a controller that returned
=(http-response "Not found" :code 404)= can =(s:abort-with 404)=
instead, and gets the application's 404 page. Writes made before an
error in a POST are rolled back; set =shiso:*atomic-requests*= to NIL
if something relied on them. Copy =static/errors/500.html= from a new
project into yours.

** Changed

- Errors in a request are answered by =wrap-http-errors=, which
  replaces =wrap-error-logging=. In debug mode an unexpected error
  shows the debug page rather than entering the debugger; =:debugp
  :repl= enters it, with a restart to retry the request.
- 404, 400 and 403 responses (unknown paths, unparsable requests, a
  bad CSRF token, guards) render through the error-page registry
  instead of fixed text. A wrong method on an existing path is a 405,
  not a 404.
- Unexpected errors' backtraces are logged without the frames of the
  error handling itself.
- =shiso:start= loads the settings, sets up the database, and serves
  from =:server/= settings; its =:host=, =:port= and =:debugp= set
  those settings for the run. An application no longer connects to
  the database or reads the environment itself.
- =:server/debugp= is true in development, so an error in a request
  shows the debug page (or, with =:debugp :repl=, opens the debugger).
  =DEBUGP=false= turns it off.
- Unhandled errors are logged once, secrets masked, never the cookies.
  Shiso always answers the 500 itself, so the error is never printed
  unmasked.
- =shiso:absolute-url= starts with =:shiso/site-origin=, or with the
  request's own scheme and host when it is for another host.
- =run-cli= loads the settings first; =setup-db= uses
  =setup-database=.
- The project template's =src/config.lisp= is replaced by
  =src/settings.lisp=.

- =shiso:current-path= returns the full request path (=script-name= +
  =path-info=), not the post-mount =path-info= alone.
- Exported =canonicalize-path= / =canonicalize-redirect-url=.

* 0.3

For sites that look and load the way their authors want.

- *Static files.* Browsers get new stylesheets and scripts as soon as
  a site is deployed, while unchanged files stay cached.
- *Forms.* A form can match a site's own design. Shiso still does the
  tedious parts (validation, error messages, keeping what the visitor
  typed, CSRF protection) without fighting generated markup, and the
  admin is unaffected.
- *Scaffolding.* New projects start with their own page skeleton and
  form components, ready to restyle.

** Added

- =shiso:cached-static= — cache-busting static URLs. With a
  =staticfiles.json= manifest (production), returns content-hashed
  paths; without one (development), appends =?v=<mtime>=. Unknown
  paths fall back to =static= and warn once.
- =(shiso:collectstatic :hash t)= — writes =stem.<12-hex>.ext=
  siblings next to unhashed copies and emits
  =<target>/staticfiles.json=. Old hashed files accumulate (rolling
  deploy safe). Nested CSS =url()= references are not rewritten.
- =shiso/static:reload-manifest= — force-reload the manifest from
  the REPL after a live collectstatic.
- Dev static middleware resolves hashed names by stripping a
  =.<hex>= segment before the extension so manifest URLs work
  against module =static/= trees.
- Direct =:ironclad= dependency (SHA-256 for fingerprints).
- Static-file unit tests in =t/static.lisp=.
- Headless forms API in =shiso/forms/context=:
  =field-context=, =form-field-by-name=, =cleaned-value=,
  =resolve-widget=, =request-form-data=. Form objects keep validation,
  coercion, sticky values, and errors as plain data; markup is optional.
- Style-dispatched =render-field= / =render-fields= (STYLE first, then
  field). Default style =t=; admin always passes =:admin= so app
  specialisations cannot clobber admin pages.
- =register-widget-field-class= / =widget-field-class=: map a model
  =:widget= keyword to a form-field class during =make-model-form=
  (built-in: =:email= → =email-field=).
- Scaffolded =src/hypermedia/form-components.lisp= with app-owned
  =ac-csrf-input=, =ac-field=, and =ac-fields= (consume =field-context=;
  restyle by editing the stamped file).
- Forms re-exported from the top-level =shiso= package for app authors.
- Todo example: model-forms for create/update, module form components,
  compact add form via =field-context=, edit route, CSRF via
  =ac-csrf-input=.
- Form tests for field-context, widgets (password/email), date parse,
  =render-fields= row ids, and =cleaned-value=.
- App skeleton =src/config.lisp=: env-backed =host=, =port=, =debugp=,
  and =database-path= (absolute XDG data-home default, =DATABASE_PATH=
  override).
- Project-wide hypermedia secondary system in the app skeleton
  (=<%application-name%>/hypermedia=) with =ac-page-skeleton=
  (charset, viewport, CSRF meta, CSS/JS hooks).
- Module skeleton =hypermedia/package.lisp= that re-exports
  module components.
- Scaffolded =main= wires =shiso:run-cli= (=createsuperuser= and
  friends) with =:setup-db= / =:serve=.

** Changed

- =render-form= injects a CSRF hidden input for non-GET methods, honours
  field =:widget= (including =:password= / =:hidden=), and accepts
  =:style=. Prefer =field-context= + components for designed pages;
  =render-form= remains for admin and prototypes.
- Auth login/signup pages use =render-form= (password widgets work);
  body data via =request-form-data=; cleaned values via =cleaned-value=.
- Admin CRUD forms pass =:style :admin= to =render-form=.
- =date-field= parse accepts HTML =date= (=YYYY-MM-DD=) and
  =datetime-local= (seconds optional); blank → =NIL=.
- Docs: forms reference (headless API, style dispatch), CSRF how-to,
  todo tutorial (05), auth tutorial (06), polls part 2 CSRF helper.
- Scaffolder template bindings:
  - =new-application= substitutes =application-name=
  - =new-module= substitutes =module-name=
  (replacing the single shared =name= key).
- Skeleton file names and package prefixes follow those keys
  (=<% @var application-name %>.asd=, =<% @var module-name %>.asd=,
  etc.).
- App =build.lisp= / =Makefile=: =vend get= then load+make via
  =build.lisp= alone.
- Docs: scaffolder how-to and CLI reference updated for the new
  placeholders and inventory.
- Routing uses *vanilla MyWay* (no namespace fork). Each module still
  has its own mapper; short route names (=:INDEX=) live on that
  mapper. =shiso:url= with ="module:route"= resolves the module, then
  looks up the short name. Removed =*global-routes-namespace*= and
  MyWay =:namespace= usage.

* 0.2 — 2026-07-17

For starting and running real projects.

- *Scaffolding.* A new project or module works from a single command,
  not by copying an example.
- *Authentication.* Sites can have users and logins without building
  them.
- *Application binaries.* A built site runs maintenance tasks, such as
  creating an administrator, from the command line.
- *Documentation.* Shiso can be learned from first tutorial to full
  reference.

This release includes the work landed through the =Updated
scaffolding= line of development.

** Added

- CLI scaffolder (=shiso new-application=, =shiso new-module=) with
  =SHISO_HOME=-aware template trees under =skeleton/=.
- Auth subsystem: sessions, CSRF helpers, login flow,
  =createsuperuser= management command.
- =shiso:run-cli= / =register-command= for application binaries.
- Basic logging support.
- Full Diátaxis documentation tree under =docs/= (tutorials, how-tos,
  reference, explanation).
- Model field-type sugar and registry introspection improvements
  (=define-model=, proper model class interning).

** Changed

- Package exports and utility surface expanded for app authors
  (=url=, CSRF token access, session table helpers, …).
- Admin links standardized on =shiso/utils:url=.

** Removed

- Literate-programming org sources as the primary code path (plain
  =src/= is canonical again).

* 0.1 — 2026-02 … 2026-03

The first release: a site built from reusable modules, with database
models, forms, and an admin for managing the data from the first day.

** Added

- Module and application macros: =define-module=,
  =define-application=, =define-route= / route table.
- Named and regex routes; request/response helpers.
- Models (Mito-backed), forms, validators.
- Admin: registry, CRUD views, module mount.
- Early scaffold for applications and modules.
- Tests for routing and related core behaviour.

** Changed

- Route API renamed toward =define-route= and clearer export sets.
