#+title: Shiso
#+author: Micah Killian

A web framework for Common Lisp.

* Requirements

- [[http://www.sbcl.org/][SBCL]] 2.x or later, on =$PATH=.
- [[https://github.com/fosskers/vend][vend]] for vendoring dependencies into your applications. Installed the
  same way as Shiso: clone, =make=, =make install=.
- GNU Make.

* Installing

#+begin_src bash
git clone <shiso-repo-url>
cd shiso
make
make install
#+end_src

After =make install= you'll have:

- =$(PREFIX)/bin/shiso= — the scaffolder binary (default prefix
  =~/.local=, override with =make install PREFIX=/usr/local=).
- =$(ASDF_DIR)/shiso/= — a full copy of the Shiso source tree (default
  =~/common-lisp/shiso/=). This is where the binary reads its skeleton
  templates from at runtime, and it's also discoverable by ASDF for REPL
  use.

The original clone is disposable after =make install= — every file the
installed system needs has been copied to its permanent location. Re-running
=make install= from any Shiso checkout overwrites the installed copy, which
is how you propagate local template customizations system-wide.

** Uninstalling

#+begin_src bash
make uninstall
#+end_src

Removes both the binary and =~/common-lisp/shiso/=.

** Overrides

| Variable   | Default               | Purpose                               |
|------------+-----------------------+---------------------------------------|
| =LISP=     | =sbcl=                | Lisp implementation used to build     |
| =PREFIX=   | =$(HOME)/.local=      | Where the =shiso= binary is installed |
| =ASDF_DIR= | =$(HOME)/common-lisp= | Where the source tree is copied       |

Example: =make install PREFIX=/usr/local ASDF_DIR=/opt=

* Using the scaffolder

The =shiso= binary has two verbs.

** Create a new application

#+begin_src bash
shiso new-application my-app
cd my-app
vend get          # fetch dependencies (including Shiso itself) into vendored/
make              # build the my-app binary
./my-app          # start the server on http://127.0.0.1:5000
#+end_src

The generated tree:

#+begin_example
my-app/
├── .gitignore
├── Makefile
├── build.lisp
├── my-app.asd
└── src/
    ├── main.lisp        # entry point: starts the server
    ├── package.lisp     # defines the my-app package
    └── routes.lisp      # one inline "home" module returning "Hello from my-app!"
#+end_example

The =.asd= file is also vend's dependency manifest — adding a system to
=:depends-on= and re-running =vend get= is all that's needed to pull new
libraries.

** Create a new module

From inside an application directory:

#+begin_src bash
shiso new-module blog
#+end_src

This stamps a module into =src/modules/blog/= with the conventional Shiso
layout:

#+begin_example
src/modules/blog/
├── blog.asd
├── blog.lisp
├── controllers.lisp
├── forms.lisp
├── hypermedia/
│   └── components.lisp
├── models.lisp
└── routes.lisp
#+end_example

After scaffolding, the scaffolder prints the lines you need to wire the
module into your application — it deliberately does *not* edit your =.asd=
file itself. Add the module to =:depends-on=:

#+begin_src lisp
:depends-on (:shiso
             :blog)
#+end_src

…and mount it in =src/routes.lisp=:

#+begin_src lisp
(s:define-application application ()
  (:modules
   ("/blog" blog)
   ("" home)))
#+end_src

Then rebuild with =make=.

* Customizing the templates

Templates live in two places under the Shiso source tree:

- =skeleton/app/= — used by =shiso new-application=
- =skeleton/module/= — used by =shiso new-module=

The scaffolder reads them from =$SHISO_HOME/skeleton/= (if set) or
=$HOME/common-lisp/shiso/skeleton/= (the install location). Substitution
syntax is the cl-emb =@var= directive — =<% @var name %>= — and the
name passed on the command line is dropped into both file paths and file
contents.

To make a customization stick system-wide, edit the templates in any Shiso
checkout (typically the one vended into an application at
=vendored/shiso/=), then =cd= there and re-run =make install=. The install
step copies that checkout — including its template customizations — into
=~/common-lisp/shiso/=, replacing the previous copy.

For one-off experiments without re-installing, point =SHISO_HOME= at a
working copy:

#+begin_src bash
export SHISO_HOME=~/code/shiso-fork
shiso new-application demo
#+end_src
