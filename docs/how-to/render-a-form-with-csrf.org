#+TITLE: How to render a form with a CSRF token
#+OPTIONS: toc:2 num:nil

Every POST/PUT/DELETE/PATCH request goes through Lack's CSRF
middleware. Forms without a valid =_csrf_token= input get rejected
with =400 Bad Request=.

GET/HEAD/OPTIONS bypass the check, so plain page rendering needs no
token.

* Prefer the scaffolded component

New applications stamped by =shiso new-application= include
=ac-csrf-input= in =src/hypermedia/form-components.lisp=. Drop it
inside every state-changing =<form>=:

#+begin_src lisp
(almighty-html:</>
 (form :method "POST" :action "/articles/save"
   (myapp/hypermedia:ac-csrf-input)
   (input :type "text" :name "title" :value title)
   (button :type "submit" "Save")))
#+end_src

* Or use the framework helper

=shiso:csrf-token-value= returns the session token (minting one on
first read). A one-liner helper:

#+begin_src lisp
(defun csrf-token-input ()
  (let ((token (and shiso:*request* (shiso:csrf-token-value))))
    (when token
      (almighty-html:</>
       (input :type "hidden" :name "_csrf_token" :value token)))))
#+end_src

* Whole-form sugar

=shiso:render-form= injects the CSRF hidden input automatically for
non-GET methods. Good for admin-style pages and prototypes:

#+begin_src lisp
(shiso:render-form form
                   :action "/articles/save"
                   :submit-label "Save")
#+end_src

For bespoke layouts, keep the =<form>= tag yourself, call
=render-fields= (or your own =ac-fields=) for the controls, and
include =ac-csrf-input= / =csrf-token-input= next to the submit
button.

* Why it works

- =shiso:*request*= is bound for the duration of every controller
  invocation.
- =shiso:csrf-token-value= reads =:lack.session= from the request
  env and asks =lack/middleware/csrf:csrf-token= for the token.
- The middleware's incoming check compares the form's =_csrf_token=
  against the session's. They match by construction.

* Test it

The polls and TODO example apps both include working CSRF flows. To
exercise one from curl:

#+begin_src bash
# 1) GET the form to establish a session + receive a CSRF token
TOKEN=$(curl -s -c cookies.txt http://127.0.0.1:5000/polls/1 \
        | grep -oE 'name="_csrf_token" value="[^"]+"' \
        | sed -E 's/.*value="([^"]+)".*/\1/')

# 2) POST with the cookie and the same token
curl -b cookies.txt -X POST \
     --data-urlencode "_csrf_token=$TOKEN" \
     --data-urlencode "choice=1" \
     http://127.0.0.1:5000/polls/1/vote
#+end_src

* AJAX submissions

When you submit a form with =fetch= or =XMLHttpRequest=, include the
token in the body or as an =X-CSRF-Token= header. The middleware
accepts both:

#+begin_src js
fetch('/save', {
  method: 'POST',
  headers: {
    'X-CSRF-Token': document.querySelector('input[name=_csrf_token]').value,
    'Content-Type': 'application/x-www-form-urlencoded',
  },
  body: 'foo=bar',
})
#+end_src

* When you don't need a token

- Safe methods: =GET=, =HEAD=, =OPTIONS=. The middleware skips them.
- API endpoints intended for non-browser clients. If you're building
  a JSON API authenticated by bearer token, you may want to bypass
  CSRF for that subtree. There's no one-flag-flips-it config yet;
  the workaround is to mount the API behind its own =define-module=
  and wrap the surrounding app with a different middleware stack.
