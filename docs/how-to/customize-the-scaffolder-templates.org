#+TITLE: How to customize the scaffolder templates
#+OPTIONS: toc:2 num:nil

The =shiso= binary's =new-application= and =new-module= commands
both copy a tree from =$SHISO_HOME/skeleton/= (default
=~/common-lisp/shiso/skeleton/=) into the current directory,
substituting =<%@var name%>= placeholders along the way. Change
those templates and your scaffolded projects look different.

* Where the templates live

#+begin_example
~/common-lisp/shiso/skeleton/
├── app/
│   ├── .gitignore
│   ├── <%@var name%>.asd
│   ├── build.lisp
│   ├── Makefile
│   ├── static/
│   │   └── .gitkeep
│   └── src/
│       ├── main.lisp
│       ├── package.lisp
│       └── routes.lisp
└── module/
    ├── <%@var name%>.asd
    ├── <%@var name%>.lisp
    ├── controllers.lisp
    ├── forms.lisp
    ├── hypermedia/
    │   └── components.lisp
    ├── models.lisp
    └── routes.lisp
#+end_example

=app/= is what =shiso new-application= stamps. =module/= is what
=shiso new-module= stamps. File names with =<%@var name%>= get the
substituted value baked into the path; file contents go through the
same substitution.

* Substitution rules

- Syntax: =<%@var KEY%>= (cl-emb's =@var= directive,
  whitespace-tolerant — =<% @var key %>= works too).
- The only key passed in today is =name= — whatever the user typed
  on the command line.
- Substitution runs over both path components and file contents.

So =<%@var name%>.asd= becomes =blog.asd= when the user runs
=shiso new-module blog=, and any =<%@var name%>= inside the file's
content becomes =blog= too.

* Quick experiment with =SHISO_HOME=

You don't have to overwrite the installed templates to try a
change. Point =SHISO_HOME= at a working copy:

#+begin_src bash
git clone <shiso-repo> ~/code/shiso
export SHISO_HOME=~/code/shiso

# edit ~/code/shiso/skeleton/app/Makefile
shiso new-application demo
cat demo/Makefile          # your edits, with `demo` substituted
#+end_src

When you're happy, =cd ~/code/shiso && make install= overwrites the
installed copy at =~/common-lisp/shiso/=.

* Common customisations

** Pre-populate =:depends-on=

Add libraries your team always uses:

#+begin_src lisp
(defsystem "<%@var name%>"
  :description "<%@var name%> application"
  :version "0.1"
  :depends-on (:shiso :str :alexandria :local-time)
  …)
#+end_src

** Default to Postgres

Edit =skeleton/app/src/main.lisp= to call
=(mito:connect-toplevel :postgres …)= with sensible defaults read
from environment variables. =gyokubundo='s main.lisp shows the
=get-env/get-env-int/envp= pattern most apps end up writing — pull
those helpers into the skeleton and stop rewriting them.

** Add a CLAUDE.md / agents instruction file

If you use Claude Code or similar tools, drop a =CLAUDE.md= into
=skeleton/app/= so every new project starts with the right project
instructions.

** Pre-mount the auth + admin modules

The scaffolded =src/routes.lisp= mounts only =home=. Change it to
the common case:

#+begin_src lisp
(s:define-application application ()
  (:modules
   ("/admin" shiso-admin)
   (""       shiso-auth)
   (""       home)))
#+end_src

…and add the matching =setup-database= boilerplate to =main.lisp=
so =shiso/auth:ensure-tables= runs at startup.

* Adding new variables to the template engine

If you want more than =name= (say, =:author= or =:license= flags),
edit =src/cli/commands.lisp= — the bindings alist is built there
and passed straight to =render:render-template=. The render
function loops over each binding and substitutes by regex, so
adding entries is a one-line change. The CLI itself currently only
parses the one positional name argument; to wire a new flag, add an
=:options= list to the relevant =clingon:make-command= form in
=src/cli/main.lisp= and read the value with =clingon:getopt= inside
the handler before delegating to =commands.lisp=.

* Restoring the defaults

The =skeleton/= directory is just files on disk under
=~/common-lisp/shiso/=. Re-run =make install= from the framework
checkout to overwrite your customisations with the canonical set.
